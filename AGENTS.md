# rust-sdk

Instructions for LLM coding assistants working in this repository. Personal additions go in a gitignored local file (`CLAUDE.local.md` for Claude Code); see [CONTRIBUTING.md](CONTRIBUTING.md#llm-coding-assistants).

## What this is

A Rust SDK for devices and controllers on Electrification Bus (eBus), which builds on the [Homie 5 MQTT convention](https://homieiot.github.io/). The protocol logic lives in sans-IO core crates that build without `std`; runtime crates drive them on tokio over MQTT. The design is in [doc/design.md](doc/design.md).

## Layout

| Path | Contents |
|---|---|
| `crates/ebus-homie/` | Homie 5 core: identifiers, topics, datatypes, `$description`, the controller state machine. No I/O, `no_std` with optional `alloc` |
| `crates/ebus-mqtt/` | MQTT vocabulary: messages, commands, topic filters, the subscription ledger. `no_std` with optional `alloc` |
| `crates/ebus-discovery/` | eBus DNS-SD contract: service types, TXT records, advertisement model, merging mDNS sightings, broker ranking and the broker search state machine. No I/O, `no_std` with optional `alloc` |
| `crates/ebus-discovery-tokio/` | mDNS backends on tokio (Avahi over D-Bus, mdns-sd): listing, finding and re-resolving brokers, and advertising a host |
| `crates/ebus-homie-tokio/` | Drives the controller on tokio over a host-owned MQTT connection |
| `crates/ebus-rumqttc/` | Bundled rumqttc 0.25 connection, its `reresolve` hook, and the `watch` and `device` examples (broker discovery through `ebus-discovery-tokio`, a dev-dependency) |
| `tools/guide-doctest/` | Unpublished crate that compiles the code in `doc/python-sdk.md` and the root README as doctests |
| `vectors/` | Cross-language test vectors, generated by `tools/gen_vectors.py` from python-sdk and python-service-discovery ([vectors/README.md](vectors/README.md)) |
| `fixtures/panel-sim/` | Masked panel captures from ebus-panel-sim, refreshed by `tools/sync-panel-sim-captures.sh` |

## Commands

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test -p ebus-discovery-tokio --features mdns-sd
cargo build -p ebus-homie -p ebus-mqtt --target thumbv7em-none-eabihf --no-default-features --features alloc
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
```

CI runs these with `RUSTFLAGS=-D warnings` on Rust 1.85, 1.91.1 and the latest stable, and builds the core crates for `thumbv7em-none-eabihf` with and without `alloc`. The end-to-end tests in `ebus-homie-tokio` and `ebus-rumqttc` start their own `mosquitto` (set `MOSQUITTO` to name the binary) and skip without one; the python-sdk interop cases also need `EBUS_PYTHON` and a `PYTHONPATH` that imports python-sdk. The mdns-sd tests in `ebus-discovery-tokio` run daemons over loopback on port 5353 and skip when two daemons cannot hear each other. The python-service-discovery interop tests in `ebus-discovery-tokio` need `EBUS_PYTHON` and a `PYTHONPATH` that imports python-service-discovery. The mDNS tests in `ebus-rumqttc/tests/discovery.rs` advertise mosquitto brokers on the interface `EBUS_TEST_MDNS_IFACE` names, which needs an IPv4 address that is not loopback and no other eBus broker, and skip without it. Tests that read a local capture corpus run only when `EBUS_CAPTURE_CORPUS` is set. With `EBUS_REQUIRE_E2E` set, as CI's discovery job sets it, the `ebus-discovery-tokio` end-to-end tests and the `ebus-rumqttc` tests that need mosquitto or `EBUS_TEST_MDNS_IFACE` fail instead of skipping when that resource is missing. A change to what goes on the wire needs the end-to-end tests too, not only a unit test.

## House style

- The core crates (`ebus-homie`, `ebus-mqtt`, `ebus-discovery`) perform no I/O, depend on no async runtime, and build without `std`: allocation behind the `alloc` feature, anything else from `std` behind `std`. Time is a caller-supplied `Instant`.
- `unsafe` is forbidden workspace-wide. The minimum Rust version is 1.85: use no API newer than that, and no API that recent stable deprecates.
- Unchanged state emits nothing: no event, no MQTT command, no snapshot republish. Deliberate re-subscribes that make the broker replay retained messages are the exception.
- The Homie 5 convention and the [eBus specification](https://github.com/electrification-bus/specification) decide wire behavior: where code and spec disagree, fix the code. Where the spec leaves a choice open, follow python-sdk. On a spec sync, update `.ebus-spec.json`.
- rustfmt defaults (edition 2024). Public items are documented; comments explain a non-obvious why, not what the code does.
- Every behavior fix comes with a test that fails without it.
- User-visible changes get an entry under `## [Unreleased]` in [CHANGELOG.md](CHANGELOG.md).

Markdown prose is written one paragraph per line, without hard wraps.
